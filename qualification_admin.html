🔴 구조적 문제 (우선 개선)

  • P1 배점이 전역 1세트뿐 — theoryPct·perfPct·crimpPct·defectPct가 모든 평가구분(신입/정기/재평가)에 공통 적용. 정기평가에 숙련도를 넣으려면 평가구분(종류)별 배점이 필요. → exam_config.trackWeights(new/regular) 도입(이번 SQL). 메인 앱은 회차 type에 따라 배점 세트를 선택하도록 패치 필요.
  • P1 숙련도(생산성) 데이터 소스 부재 — ⑥ 숙련도 탭은 총점을 등급으로 바꿔 보여줄 뿐, 생산성 지표가 없음. 다기능 등급도 합격 공정 수로 하드코딩(3=다기능, 4=숙련, 5=최고수). → exam_productivity(일자별 목표/실적/불량) + 달성률→점수 구간표(profBands) + 최소 실적일수(profRule). ③ 탭에서 MES/작업일보 붙여넣기.
  • P1 과목별 과락 없음 — 합격 기준이 총점 60점 하나. 이론 0점이어도 작업수행 40+MSA 30=70점으로 합격 가능. → 과목별 최소 득점률(minPct) 추가 — 예: 이론 50%·작업수행 60%·MSA 합격 필수. ②에서 설정, 시뮬레이션에서 확인.
  • P1 기록 분리·중복 — 같은 사번·같은 평가구분 기록 중복 그룹, 평가구분 미지정(null)과 지정 기록이 동시에 있는 사번 다수(10-27 MSA 트리거가 activeRound 미설정 상태에서 생성). 결과 이력·숙련도 집계가 어느 기록을 쓸지 규칙(_latestResult)에 의존. → 사번+평가구분 1행 원칙: DB unique 제약 또는 upsert RPC(exam_upsert_result)로 통일, 미지정 52건은 결과 이력 「일괄 지정」으로 NEW-2026-10에 귀속 후 병합.

🟠 판정·점수 로직

  • P2 압착고 점수가 0/15 이분법 — GR&R 결과 Aprobado면 15점, 아니면 0점. 우수(%Study<10)와 양호(≤30)가 같은 점수. → 등급 연동: 우수 100% · 양호 80% · 부족 0% (또는 %Study 선형 환산). 재평가 합격은 상한 80% 등 차등 가능.
  • P2 MSA는 조(組) 단위 판정 — 계량형 GR&R은 3인 1조 결과를 개인에게 동일 부여(10-27 결정). 조원 1명의 편차로 3명이 동시에 불합격/합격되므로, 개인 식별 지표(fault_ops·측정자별 편차)를 개인 점수에 반영할 여지. → fault_ops에 포함된 측정자는 개인 감점(예 −5) 옵션.
  • P2 이론 원점수 체계 불일치 — 모바일 응시는 raw=정답수/raw_max=문항수(20), 설정 pointsPerQ=5는 100점 기준. 레코드마다 raw_max가 다름(trg_normalize_theory가 보정). → 원점수는 「정답수/문항수」로 고정하고 pointsPerQ 설정은 제거 또는 표시용으로만.
  • P2 등급 기준 중복 — exam_grade_config에 S와 L0가 둘 다 95점(동점 2개 라벨). 정렬 순서에 따라 라벨이 달라짐. → L0~L5 또는 S/A/B/C/D 중 하나로 통일. 정기평가는 숙련도 포함 총점 기준 L등급, 신입은 합격/불합격만.
  • P2 항목 식별이 이름 정규식 — /작업수행|desempe/, /압착|altura/ 로 항목을 찾음. 항목명을 바꾸면 채점·집계·DB 트리거(exam_msa_sync의 n_perf 등)가 동시에 깨짐. → exam_practical_items에 kind('perf'|'crimp'|'defect') 컬럼 추가, practical_item_scores에도 kind 저장.

🔵 운영·유지보수

  • P3 테스트/실데이터 미구분 — 임의데이터를 넣으면 실 통계에 섞임. → is_dummy 컬럼(이번 SQL) + 임의 사번 규칙(M0YYMM99xx) + 일괄 삭제 RPC.
  • P3 날짜가 text — exam_results.date·hire_date·exam_students.hire_date 모두 text. 기간 필터·근속 계산이 문자열 비교. → date 타입 컬럼 병행 추가 후 전환.
  • P3 평가자·근거 추적 부재 — 작업수행 체크시트에 평가자(조장/관리자)·평가일시·서명이 없음. 감사(IATF 7.2 역량 기록) 대응 시 근거 부족. → sheet에 evaluator·evaluated_at 추가, 결과 PDF 출력.
  • P3 6개 파일 템플릿 재생성 구조 — 1공장 가공 수정 → 6파일 재생성. 숙련도 반영은 팀마다 지표가 달라(조립은 UPH→C/T 기준 L1~L5) 공통 템플릿에 분기 필요. → 팀별 설정(exam_config.track/prof)만 다르게 두고 로직은 공통 유지.
  • P3 anon 키 전권 — 모든 exam_* 테이블에 anon 삭제·수정 허용(RLS true). 포털 로그인과 무관하게 URL만 알면 수정 가능. → 쓰기는 RPC로 모으고 portal_session 토큰 검증 또는 배점·설정 변경은 관리자 PIN 확인.
